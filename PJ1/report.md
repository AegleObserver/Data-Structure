# 数据结构课程项目报告

## 祖玛彩球连锁消除 —— 命令行版

---

## 一、项目概述

### 1.1 项目背景

祖玛是一款经典的彩球消除游戏。彩球沿轨道移动，玩家发射彩球插入轨道，当三个或更多同色彩球连续相邻时即被消除，消除后两侧球接上可能触发连锁消除。本项目以命令行形式实现该游戏的核心玩法。

### 1.2 开发环境

| 组件 | 说明 |
|---|---|
| 操作系统 | Windows 10/11 |
| 编译器 | g++ (MSYS2 UCRT64, 支持 C++11) |
| 构建工具 | GNU Make |
| 依赖 | 仅标准库与 Windows API，无第三方库 |

### 1.3 功能清单

**必做内容（对应题目五项基本功能）**

- 关卡选择与文件读取（内置新手教程 + 7 个关卡）
- 彩球插入 / 丢弃（含非法输入处理）
- 普通消除与连锁消除
- 轨道自动补充（每回合从等待区补一球）与上限判负
- 游戏状态显示与胜负判断

**延伸内容（可选扩展）**

- 撤销 / 重开
- 消除分步动画（插入 → 消除 → 连锁，每步 0.5s）
- 五种游戏模式：普通 / 无尽 / 限时（2 分钟）/ 生存 / 变色龙
- 彩色终端界面（清屏刷新、进度条、彩色球）
- 新手引导教程（固定操作脚本、箭头与文字提示）
- 暂停 / 快捷存档 / 读档
- 排行榜（本地持久化）
- 音效开关（Beep）
- 设置菜单（生存模式限时 / 音效）

## 二、需求分析

### 2.1 基本功能

1. **关卡选择与读取**：从 `levels/` 目录读取关卡文件，解析 ACTIVE / FEED / AMMO / MAX_LENGTH 四个字段（可选 TUTORIAL 标记引导教程）。
2. **彩球发射、插入与丢弃**：玩家持有当前球与下一个球，每回合可插入到指定位置或直接丢弃。非法输入不消耗彩球、不使轨道增长。
3. **普通消除与连锁消除**：插入后若形成 3+ 连续同色球则消除，消除后检查接缝处是否形成新连续，循环至无可消除。丢弃不触发消除。
4. **轨道自动补充**：每次有效回合结束，从 FEED 队列取一球进入轨道；FEED 为空时不再加入。轨道球数超过 MAX_LENGTH 则失败。
5. **游戏状态与胜负判断**：显示球链、当前球、下一个球、等待区、得分、回合数、时间。轨道与等待区全空 → 胜利；轨道超限 → 失败。

### 2.2 关卡文件格式

```
ACTIVE=RRBBRR
FEED=GBYPRGBGYRBPYG
AMMO=BBGYRRGBYPRG
MAX_LENGTH=12
TUTORIAL=0
```

- `ACTIVE`：初始轨道上的球
- `FEED`：等待进入轨道的球（每回合进一个）
- `AMMO`：弹药循环序列（第 1 字符 = 初始当前球，第 2 字符 = 初始下一个球，循环使用）
- `MAX_LENGTH`：轨道球数上限
- `TUTORIAL`（可选）：置 1 时该关为引导教程，启用固定操作脚本与提示

### 2.3 回合流程

```
玩家输入 → 插入/丢弃 → 消除/连锁（仅插入时）→ 补一个 FEED 球 → 更新当前/下一个球 → 判胜负
```

## 三、总体设计

### 3.1 模块划分

| 模块 | 文件 | 职责 |
|---|---|---|
| 核心逻辑 | `GameModule.h/cpp` | 球链、插入、消除、计分、变色标记、存档/读档、快照 |
| 文件读取 | `FileReader.h/cpp` | 从 `levels/` 读取并解析关卡文件 |
| 终端界面 | `TerminalUI.h/cpp` | 彩色显示、输入、限时输入、菜单、动画、教学提示 |
| 游戏流程 | `Tunnel.h/cpp` | 回合循环、弹药、补球、计时、撤销、教程脚本、排行榜、设置 |
| 排行榜 | `RankBoard.h/cpp` | 排行榜存储、排序、显示 |
| 入口 | `Init.cpp` | main 函数 |

### 3.2 游戏状态模型

```
GameModule
├── balls (string)          —— 球链轨道
├── feedQueue (deque<char>) —— 等待区
├── ammo (string)            —— 弹药序列
├── ammoIndex (int)          —— 弹药循环索引
├── currentBall / nextBall  —— 当前球 / 下一个球
├── maxSize (int)           —— 轨道上限
├── score (int)             —— 得分
├── turnCount (int)         —— 回合数
└── marks (vector<char>)    —— 变色标记（与球链等长）
```

### 3.3 游戏模式

| 模式 | 说明 |
|---|---|
| 普通 | 在轨道超过上限前清空所有球 |
| 无尽 | FEED 用完后随机补球，尽可能生存 |
| 限时 | 总限时 2 分钟，倒计时走完前清空所有球即胜利 |
| 生存 | 上限 50 球，消除可延长时间；初始限时默认 60 秒（可在设置中调整）；时间耗尽或轨道超限即失败 |
| 变色龙 | 每次释放彩球后，轨道中随机一球变为随机异色并以 `^` 标出 |

## 四、数据结构选型

### 4.1 `std::string`（动态数组）—— 球链轨道

**使用位置**：`GameModule::balls`

**选择原因**：
- 球链需要频繁在任意位置插入（`balls.insert(index, 1, ball)`）和删除（`balls.erase(l, len)`）
- 消除判定需要随机访问插入点附近的球（`balls[l-1] == c`）
- `std::string` 支持 O(1) 随机访问，插入/删除为 O(n) 搬移，在球链长度有限（≤50）时完全可接受

**对比链表**：链表虽然插入删除 O(1)，但随机访问 O(n)，而消除判定需要频繁定位插入点附近的球，`string` 的随机访问更高效。

### 4.2 `std::deque<char>`（双端队列）—— FEED 等待区

**使用位置**：`GameModule::feedQueue`

**选择原因**：
- FEED 是严格的 FIFO 队列：初始化时从尾部批量入队，每回合从队首取一个球
- `std::deque` 的 `push_back` / `pop_front` 均为 O(1)，天然匹配队列语义
- 比 `std::queue` 更灵活，支持遍历（用于界面显示等待区内容）

### 4.3 `std::vector<RankEntry>` —— 排行榜记录

**使用位置**：`RankBoard::entries`

**选择原因**：
- 排行榜记录数量不定，需要动态扩容
- 需要按不同规则排序（通关按用时、未通关按分数），`std::vector` 配合 `std::sort` + lambda 比较器最简洁
- 支持随机访问，便于分页显示前 10 名

### 4.4 `struct Snapshot` + `std::vector`（栈）—— 撤销历史

**使用位置**：`Tunnel::history`

**选择原因**：
- 每回合开始前保存快照，撤销时弹出栈顶恢复
- 栈的 LIFO 特性完美匹配"撤销最近一步"的语义
- 限制栈深度为 100，防止内存无限增长

### 4.5 取模索引（环形缓冲区思想）—— 弹药循环

**使用位置**：`GameModule::advanceAmmo()`

**选择原因**：
- 弹药序列 `AMMO` 用完后从头循环，`index % size` 一行实现
- 无需额外数据结构，取模运算即为最简洁的环形缓冲区

### 4.6 `std::function`（回调）—— 消除分步动画

**使用位置**：`GameModule::resolve` 的 `ElimCallback`

**选择原因**：
- 消除过程需要分步展示（插入 → 第一次消除 → 连锁消除），每步间隔 0.5s
- 通过回调将"状态变化"通知给 UI 层，保持 GameModule 不依赖 TerminalUI
- 回调参数：(当前轨道, 动作类型, 消除起始, 消除长度, 连锁层数)

### 4.7 文件 I/O 序列化 —— 存档/读档

**使用位置**：`GameModule::save` / `GameModule::load`

**选择原因**：
- 将游戏状态序列化为 key=value 文本格式，与关卡文件格式一致
- 可读性好，便于调试；反序列化时逐行解析恢复状态

### 4.8 `std::vector<char>`（并行标记数组）—— 变色标记

**使用位置**：`GameModule::marks`

**选择原因**：
- 变色龙模式需要记录"哪一个球刚被改变颜色"，且球链会频繁插入 / 删除
- 标记数组与球链等长，插入 / 消除 / 补球时同步更新，保证下标始终对齐
- 只保留最近一次被变色的球（每次变色先清空再置 1），避免标记越积越多
- 快照（撤销）复制该数组，撤销后标记随球链一起还原

## 五、核心算法

### 5.1 插入与合法性校验

```cpp
bool insertBall(char ball, int index) {
    if (index < 0 || index > (int)balls.size()) return false;
    balls.insert(index, 1, ball);
    resolve(index, callback);
    return true;
}
```

- 索引越界 → 返回 false，不消耗球、不增长轨道
- 合法则插入并触发消除判定

### 5.2 消除判定（局部扫描）

**关键观察**：插入只可能让"插入点所在的那一段同色球"达到 3 个，其他段未被碰过。

```cpp
// 从插入点向左右扩展，找到同色段边界
while (l > 0 && balls[l-1] == c) --l;
while (r + 1 < size && balls[r+1] == c) ++r;
int len = r - l + 1;
if (len >= 3) → 消除
```

**复杂度**：O(k)，k 为同色段长度，与整链长度无关。

### 5.3 连锁消除

**关键观察**：消除后只可能在"接缝处"（被消段的两侧交界）产生新的连续段。

```
消除 [l, r] 后：
  若 l == 0 或 l >= size → 链头/链尾，无接缝，结束
  若 balls[l-1] != balls[l] → 接缝两侧不同色，结束
  否则 index = l，继续循环检查接缝处
```

每次循环至少消 3 个球，循环次数 ≤ 总球数/3，均摊 O(1)。

### 5.4 计分规则

```
得分 = 本次消除球数 × 20 × 加分系数
加分系数 = 1.0 + (本次消除球数 - 3) × 0.2
```

| 消除球数 | 加分系数 | 得分 |
|---|---|---|
| 3 | 1.0 | 60 |
| 4 | 1.2 | 96 |
| 5 | 1.4 | 140 |
| 6 | 1.6 | 192 |

### 5.5 限时/生存模式计时

- **限时模式**：总限时 2 分钟（`TIMED_LIMIT_MS = 120000`），倒计时实时运行（输入时通过 `_kbhit` 轮询，时钟照走），暂停不计时
- **生存模式**：初始 60 秒（可在设置中调整，10–600 秒），每次消除奖励 `len × chainLevel × 0.5s`，时间耗尽或轨道超 50 → 失败

### 5.6 计时器实现

```cpp
long long currentElapsedMs() const {
    auto now = isPaused ? pauseStart : steady_clock::now();
    return duration_cast<milliseconds>(now - startTime).count() - totalPausedMs;
}
```

- `startTime`：游戏开始时刻
- `pauseStart`：暂停开始时刻
- `totalPausedMs`：累计暂停时长
- 暂停时 `now` 固定为 `pauseStart`，不再增长

### 5.7 变色龙模式（随机变色 + 标记）

```
每次回合结束（插入或丢弃）：
  若轨道非空 → 随机取一球 i，随机换成与当前不同的颜色
  marks 全部清 0，marks[i] = 1；界面在球链下方以 ^ 标出
```

- 变色不触发消除：三连是否成立由玩家后续操作决定，行为可预期
- 每次仅标记最近一变色球，箭头随后续回合更新
- 插入 / 消除 / 补球 / 快照均同步维护 marks，保证下标始终对齐

## 六、功能实现与异常处理

### 6.1 彩色终端界面

- 使用 Windows API `SetConsoleTextAttribute` 设置前景/背景色
- 每次显示前 `system("cls")` 清屏，实现刷新无偏移
- 球用 `O` 字符 + 颜色区分（R 红 / G 绿 / B 蓝 / Y 黄 / P 紫）
- 进度条用 `#` / `-` 显示轨道占用率
- 消除动画：被消球以白底红字高亮，分步展示，每步间隔 500ms

### 6.2 输入处理

- **数字**（如 `3`）→ 默认将当前球插入到该位置
- **字母** → 执行对应功能：`d` 丢弃、`u` 撤销、`r` 重开、`s` 存档、`p` 暂停、`q` 退出
- 非法输入（非数字非字母、索引越界）→ 提示重试，不消耗球、不增长轨道
- 限时/生存模式：输入通过 `_kbhit` 轮询，时钟实时倒计时

### 6.3 暂停 / 撤销 / 重开 / 快捷存档

- **暂停**（`p`）：显示暂停菜单（继续 / 回主菜单），暂停期间计时不走
- **撤销**（`u`）：弹出栈顶快照恢复，最多 100 步
- **重开**（`r`）：清空历史栈，重新初始化当前关卡
- **快捷存档**（`s`）：序列化当前状态到 `saves/save.txt`，不中断游戏

### 6.4 新手引导教程

- 教程关卡 `levels/tutorial.txt`（`TUTORIAL=1`），轨道 / FEED / 弹药固定，共 4 步：
  插入消除 → 观察补球 → 丢弃 → 获胜
- 脚本表 `TUTORIAL_STEPS` 描述每一步：期望输入、箭头位置、提示文字
- 每步只接受脚本指定的输入，其他输入给出提示并等待重试，不消耗回合
  （`p` / `q` / `r` 仍可用，暂停、退出、重开不受限制）
- 界面在轨道下方以 `^` 箭头标出建议插入位置，并显示当前步骤提示
- 教程局结算不计入排行榜

### 6.5 排行榜持久化

- 格式：`name|level|mode|result|score|timeMs|date`（管道分隔）
- 通关记录按用时升序，未通关按分数降序，各显示前 10 名
- 文件路径：`saves/rank.txt`

### 6.6 音效

- 使用 Windows `Beep(freq, duration)` 实现
- 插入：440Hz 短音；消除：660→880Hz 双音；连锁：880→1100→1320Hz 三音
- 胜利：C-E-G 上行；失败：下行双音
- 设置菜单可开关（默认关闭）

### 6.7 设置菜单

- **生存模式起始限时**：输入 10 - 600 秒并校验范围，菜单实时显示当前值（默认 `01:00`）
- **音效开关**：默认关闭

## 八、总结与心得

### 8.1 遇到的问题与解决方案

| 问题 | 解决方案 |
|---|---|
| Unicode 边框在 cmd 乱码 | 改用纯 ASCII 字符（`|`、`-`、`=`） |
| 球颜色不显示 | `colorBall` 先设色再恢复导致颜色丢失，改为 `printBall` 直接输出带色字符 |
| 界面滚动偏移 | 每次显示前 `system("cls")` 清屏刷新 |
| 游戏结束画面被菜单清掉 | 胜负画面后加 `pauseScreen()` 等待玩家确认 |
| EOF 输入导致无限循环 | `getMainChoice` 检测 `cin` 失败时返回 0（退出） |
| 限时模式输入时时钟不走 | 改用 `_kbhit` 轮询输入，时钟实时倒计时 |
| 修改头文件后旧目标文件未重编译，类布局不一致导致运行时崩溃 | Makefile 加入 `-MMD -MP` 跟踪头文件依赖，头文件变更自动重编译 |

### 8.2 设计取舍与优化思路

- **球链用 `string` 而非链表**：消除判定需要频繁随机访问，`string` 的 O(1) 随机访问比链表的 O(n) 遍历更高效
- **FEED 用 `deque` 而非 `queue`**：`deque` 支持遍历，便于界面显示等待区内容
- **消除判定只扫描局部**：不遍历整链，只从插入点向左右扩展，复杂度 O(k) 而非 O(n)
- **快照栈限制 100 步**：防止内存无限增长，同时覆盖绝大多数撤销需求
- **回调实现分步动画**：GameModule 不依赖 UI 层，通过 `std::function` 回调通知状态变化
- **变色标记用并行数组而非下标列表**：球链插入 / 删除会整体移位，并行数组随链同步操作最不易错位

### 8.3 可改进方向

- 图形界面（Qt / SFML）
- 关卡编辑器
- 更多关卡与难度曲线
- 网络排行榜
- 更丰富的音效与背景音乐
